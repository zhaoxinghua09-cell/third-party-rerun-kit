# E5 严格合格线：按建议执行（2026-11-26）

上轮的建议是「合格线追加 passed≥3 且测试内含断言或状态比对，D 档强制复核」。本轮照此执行并重算读数。

## 新口径

```
严格合格 = passed >= 3
        且 测试文件内至少出现一处断言（assert / assertEqual / pytest.raises / expect 等）
           或至少一处状态比对（== / !=）
```

不合格件不再笼统记为 "pass"，而是分成三档：`pass_strict` / `pass_thin` / `n/a`（非 pass）。

## 执行方式（不是重跑，是逐件取证）

1. 取 36 件 `pass` 的仓库，按 `verification_entries` 抓测试文件；
2. 统计其中的断言数量与状态比对；
3. 4 件入口只标了 `deep:unittest` / `deep:pytest`（无具体路径），改用全树扫描定位测试文件后补证；
4. 复核：4 件均含状态比对，判定为达标；2 件（各 1 条通过、测试内 0 断言且无状态比对）判为薄。
