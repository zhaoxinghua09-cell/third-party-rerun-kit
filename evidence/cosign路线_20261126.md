# cosign 路线：从坏文件到跑通（2026-11-26）

## 一、先解决"二进制是坏的"

之前的事实：官方 release v3.1.5 的 `cosign.exe` 应为 **191,166,976 B**，本机只拿到 32,505,856 B（约 17%），PE 头不完整、不可执行。

这次重下，判据不再是"文件大于 1 MB 就算成功"，而是**先读 release 元数据里的 size，再逐字节比对**：

```
release: v3.1.5
官方 size = 191,166,976 B
try 1: downloaded 191,166,976 B / expect 191,166,976 B
sha256: b7716eaca8d592869feeffbcb4f826963f2feba3c5e72a03019fe024059ad1fc
OK D:\Workbuddy\tools\cosign\cosign.exe
```

这一次是完整的。

## 二、v3.1.5 的接口已经变了（踩了三个坑）

1. `--output-signature` / `--signature` 已弃用，必须用 `--bundle`；
2. 只用 `--bundle` 会报 `must specify --bundle with --new-bundle-format`；
3. `--tlog-upload=false` 不再被接受，要求改用 **signing-config**：

```
Error: --tlog-upload=false is not supported with --signing-config or --use-signing-config.
Provide a signing config with --signing-config without a transparency log service
```

正解：

```bash
cosign signing-config create --out signing-config.json      # 不指定任何服务 → 无 Rekor
cosign sign-blob --key cosign.key --signing-config signing-config.json --bundle cosign.bundle key-statement.json
cosign verify-blob --key cosign.pub --bundle cosign.bundle --insecure-ignore-tlog=true key-statement.json
```

生成的 `signing-config.json` 只有 106 B：`{"mediaType":"...v0.2+json","rekorTlogConfig":{},"tsaConfig":{}}`——确实是"没有透明日志服务"。

## 三、实跑结果（含反例）

```
sign-blob  → Wrote bundle to file cosign.bundle        (387 B)
verify-blob（原件）→ Verified OK
verify-blob（把第 40 字节翻转）→ Error: failed to verify signature:
                              invalid signature when validating ASN.1 encoded signature
```

正例通过、反例被拒，这才叫跑通——只看"签名命令没报错"不算。

## 四、这条链的真相：它比 Rekor 弱，必须写清楚

`verify-blob` 必须加 `--insecure-ignore-tlog=true` 才能过，cosign 自己每次都打印：

```
WARNING: Skipping tlog verification is an insecure practice that lacks transparency and auditability verification for the blob.
```

含义直白：**这次签名没有进透明日志**。所以：

- 能证明：这个 blob 的签名与这把 cosign 公钥匹配、内容未被改；
- 不能证明：签名发生在何时、是否被登记进公开日志、是否可被第三方事后独立查到。

要补上后半截，必须真的把条目写进 Rekor（需要 OIDC 登录或上传权限），这一步**本轮没做**。

## 五、和 Ed25519 那条路径的关系

| | Ed25519 自包含 | cosign（本轮） |
|---|---|---|
| 依赖 | 只需 `cryptography` | 需 cosign 二进制 191 MB |
| 时间锚 | OTS → 比特币 977531/977532 | 无（tlog 被跳过） |
| 透明日志 | 无 | **有接口但本次未启用** |
| 结论 | 已完整闭环 | 签名/验签闭环，透明日志未闭环 |

两条并行没有坏处：Ed25519 轻、可离线；cosign 是生态通用格式，将来若真接 Rekor，可以只换这一层。

## 六、安全事项：先别推仓库

跑 demo 生成的 `cosign.key`（私钥，653 B）目前还落在 `public_repro\trust\` 目录里。**在它被移出之前，一次推送都不能做**，否则私钥会进公开仓。

我提了"把私钥移到 `keys\cosign_demo.key`、并删掉测试残留 `tampered.json`"这一步，等待确认时超时未执行。所以本轮**没有推送任何文件**——这是有意为之，不是漏做。

待你确认后要做的三件事：

1. `cosign.key` → `keys\cosign_demo.key`（公开目录里只留 `cosign.pub` 178 B 与 `cosign.bundle` 387 B）；
2. 删 `tampered.json`；
3. `publish_repo.py` 的排除规则再加上 `cosign.key`、`tampered.json`、`*.key` 三条兜底，再推送。
