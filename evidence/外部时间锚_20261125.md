# 外部时间锚：五条路的实探与选择 · 2026-11-25

上一轮卡在"没有域名，所以 DNS 锚只能写不能跑"。这轮不再猜，把五条可选的外部锚全部实探一遍，选一条今天就能跑、且**不需要域名、不需要账号所有权**的。

## 一、实探结果（都是真发请求，不是查文档）

| 候选 | 端点 | 可达性 | 需要什么 | 信任模型 |
|---|---|---|---|---|
| OpenTimestamps 日历 | `a.pool.opentimestamps.org` | **200**（4.5s） | pip 客户端，无需账号 | **无需信任任何组织**（落在比特币 PoW） |
| FreeTSA（RFC 3161） | `freetsa.org` | **200**（1.1s） | DER 编码请求，免费 | 信任这家 TSA；社区对其"可信度"评价为 No |
| Sigstore Rekor | `rekor.sigstore.dev` | **200**（1.0s） | cosign + OIDC 登录 | 透明日志，但 Sigstore 运营方是单点 |
| sigstore 搜索 | `search.sigstore.dev` | **200**（0.9s） | 同上 | 同上 |
| PyPI（装 OTS 客户端） | `pypi.org` | **200**（1.5s） | 无 | — |
| DANE / TLSA（DNSSEC） | 需自有域名 | **不可做** | 域名 + DNSSEC 签名 | 最硬（DNSSEC 链到根），但没有域名就跑不了 |

## 二、为什么选 OpenTimestamps

1. **不需要域名、不需要账号**——正好绕过我们的阻塞点；
2. **不需要信任谁**：它把哈希并进 Merkle 树，根写进比特币交易；验证只看区块头，不看运营方（IETF 有两份草案把它当外部时间锚：`draft-fassbender-scitt-time-anchor`、`draft-reilly-cts` 的 Layer 3）；
3. **今天就能跑**：`pip install opentimestamps-client` → `ots stamp` → 拿 `.ots` 证明。

## 三、已经做了什么（可核对）

```
ots stamp trust/ed25519.pub            → trust/ed25519.pub.ots           (1190 B)
ots stamp trust/key-statement.json     → trust/key-statement.json.ots    ( 945 B)
```

两份证明各提交到 **4 个独立日历**（opentimestamps.org 的 alice/bob、eternitywall 的 finney、catallaxy 的 btc）：

```
日历 attestation: 4 个  ['finney.calendar.eternitywall.com', 'alice.btc.calendar.opentimestamps.org',
                        'btc.calendar.catallaxy.com', 'bob.btc.calendar.opentimestamps.org']
比特币区块 attestation: 0 个
OTS_STATUS = PENDING_CALENDAR
```

**这一刻的准确说法**：我们已经把公钥（及一份公钥公开声明）的哈希提交进日历的 Merkle 树，**但还没进比特币区块**。所以现在只能说"我们提交过"，**不能说"已锚定"**。上链通常几小时内，届时 `ots upgrade` 把证明补成比特币 attestation，再用 `ots verify`（需区块头）才是真正的独立可验。

## 四、锚的三层，现在到第几层

| 层 | 机制 | 状态 | 能防什么 | 防不了什么 |
|---|---|---|---|---|
| L1 账号锚 | `anchor.json` 钉 GitHub commit | **已跑通**（A10 实测拦下换钥） | 换钥 | 账号被盗、强推改历史 |
| L2 时间锚 | OpenTimestamps | **已提交，待上链** | "这份公钥不晚于某时点存在"、事后伪造时间线 | 上链前不能当锚用 |
| L3 域名锚 | DANE/TLSA + DNSSEC | **不可做**（无域名） | 把钥匙绑到域名控制权 | 需域名与 DNSSEC 运维 |

L1+L2 合起来已经能说一句以前不能说的话："**这把公钥在某时点前公开过，且此后换钥会被发现**"。仍然**不能**说"这是我做的"——那需要 L3 或某个别人已认识的指纹。

## 五、下一步（按可做性排）

1. **等上链**：几小时后 `ots upgrade` 两份证明，再 `ots verify`，把状态从 PENDING 改成 BITCOIN_CONFIRMED。这一步不需要新资源，只需要时间。
2. **有域名时上 L3**：`_key.<domain>` TXT 或 `/.well-known/uibc-key.txt` + DNSSEC，把锚从"账号级"提到"域名级"。
3. **Rekor 互通**：需要 cosign 完整包（本机只取到 17%）与 OIDC 登录，暂不推进。

## 六、这轮没有做的事（别以为做了）

- 没有装 cosign、没有往 Rekor 写任何东西；
- 没有域名，DANE 一个记录都没发；
- 没有对 FreeTSA 发 RFC 3161 请求（可达但"信任一家 TSA"不如 OTS 的模型干净，且它自己声明"可信度 No"）；
- `ots verify` 还没跑过——因为证明尚未上链，现在跑只能得到 PENDING，跑不出"已验证"。
